# Gateway budget denial and plan-stage overage escaped workflow results

**Date:** 2026-11-20 01:28
**Files:** src/lean_weave/workflow/orchestrator.py, tests/workflow/test_orchestrator.py
**Severity:** high

## Problem

Verification of v1-06 found two budget paths that did not produce the required
`budget_exhausted` workflow result:

1. A gateway `BudgetExceededError` raised by `LLMProvider.complete` escaped
   `run_feature`/`run_simple`/`resume`. The checkpoint stayed at its current
   stage with no terminal status and callers received no structured result.
2. A reported plan-completion overage was converted to
   `failed` / `plan_call_unavailable` instead of
   `budget_exhausted` / `feature_token_overage`.

Both contradicted ADR-004 and the v1-06 requirement to expose budget exhaustion
separately while retaining a compatible `FeatureState.stage`.

## Root Cause

`BudgetExceededError` is a peer of `ProviderError`, not a subclass. The driver
only translated `WorkflowBudgetExceeded` and `ProviderError`, so gateway
admission/overage failures fell through the stage dispatch boundary uncaught.

`_plan_stage` treated every `ToolLoopOutcome.exhausted` result as unavailable,
unlike `_run_tool_stage`, which checks `outcome.overage` before `exhausted`.
The plan path therefore lost the distinction between "no usable plan call" and
"the call succeeded but exceeded the budget".

## Solution

- Catch `BudgetExceededError` in `_drive` and project it through
  `_budget_terminal` with the stable code `gateway_budget_denied`, so the
  checkpoint and result both report budget exhaustion.
- Check `outcome.overage` before `outcome.exhausted` in `_plan_stage` and raise
  `WorkflowBudgetExceeded(FEATURE_TOKEN_OVERAGE)`, matching the implement and
  retry path.
- Emit metadata-only `[Workflow.budget]` warnings for both paths; no prompt,
  usage value, or gateway text is logged.
- Added regression tests for gateway denial, plan-stage overage, and the
  non-blocking `VerificationStatus.WARN` success path.

## Prevention

- Translate every accounting exception that crosses the provider boundary at
  the driver boundary; do not assume provider errors share a hierarchy.
- Keep plan/implement/retry outcome handling symmetric so an overage code
  cannot be downgraded to a generic stage failure.
- Cover both pre-dispatch refusal and post-call reported overage for every LLM
  stage, not only the implement stage.
- Keep a non-blocking verification warning in the success-path regression set.

## Regression Evidence

The two new budget tests failed before the change (one propagated
`BudgetExceededError`; the other returned `failed`/`plan_call_unavailable`) and
pass afterward. The WARN verification test passes and protects the existing
success path. Full offline suite: 496 passed, 1 skipped.
