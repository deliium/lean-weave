# Protect CLI error output and contain YAML parser recursion

**Date:** 2026-11-16 22:13 UTC
**Files:** src/lean_weave/logging_setup.py, src/lean_weave/cli/app.py, src/lean_weave/cli/__init__.py, src/lean_weave/config/loader.py, tests/cli/test_cli.py, tests/config/test_config_loader.py
**Severity:** high

## Problem

A synthetic current API-key value embedded in a missing configuration filename
was echoed by the CLI error boundary, although the corresponding log was
redacted. Deeply nested YAML raised an uncaught `RecursionError` rather than
the required configuration exit code 3.

## Root Cause

Logging filters protect handler output, not direct `typer.echo` calls.
Application exceptions were assumed to be safe because their messages excluded
configuration payloads, but their filenames were still untrusted. The YAML
boundary caught `yaml.YAMLError` only; recursive parser failures use the
standard-library `RecursionError`.

## Solution

Apply a shared console-message redactor at both CLI error boundaries, covering
application and Click exceptions. Always apply the default key filter and reuse
application-owned configured filters for custom secret-env names after loading.
Catch `RecursionError` only around YAML parsing and convert it to a sanitized
`ConfigError`, preserving the file/position diagnostic without exception text.
Keep configurable `[FIX]` debug diagnostics free of input payloads.

## Prevention

- Test direct stderr output independently of logging output.
- Exercise untrusted filenames as well as YAML field values.
- Reuse configured redaction filters instead of maintaining a second secret store.
- Test real deeply nested YAML plus a deterministic parser exception sentinel.
- Custom secret names cannot be discovered from an invalid/unloaded configuration;
  do not claim they are known before successful validation.
- Consider broader YAML fuzz tests for future hardening.

## Regression Evidence

Three targeted tests failed before the fixes and passed afterward.
Two additional tests cover custom-key errors after configuration and safe
parser recursion diagnostics. Offline core/full suites pass with the default
key unset and with a dummy value: 115 / 123 tests respectively.
