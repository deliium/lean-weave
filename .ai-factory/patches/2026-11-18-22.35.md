# Disable production redirects and fail closed on dangling usage journals

**Date:** 2026-11-18 22:35
**Files:** src/lean_weave/providers/deepseek.py, src/lean_weave/metrics/jsonl.py, tests/providers/test_deepseek.py, tests/metrics/test_jsonl.py, tests/cli/test_llm.py
**Severity:** high

## Problem

Three defects survived the v1-03 offline verification:

1. The production DeepSeek client followed HTTP redirects. Redirect following
   was disabled only when a transport was injected, so the real path used the
   SDK default client, which sets `follow_redirects=True`. The documentation
   claimed redirects were disabled.
2. `JsonlMetricsCollector.spent()` and `summary()` returned zero for an internal
   dangling journal symlink because `Path.exists()` follows symlinks. Spend was
   silently reset instead of failing closed.
3. Journal append/replay failures emitted no `ERROR` record, and a successful
   attempt with incomplete usage emitted no warning. A new test also violated
   the top-level-import rule by importing inside a helper function.

## Root Cause

- The client construction branch treated "injected transport" as the only
  reason to own an HTTP client. The default SDK wrapper was assumed to match
  the gateway's redirect policy, but the SDK explicitly sets
  `follow_redirects=True` in `_DefaultHttpxClient`.
- Absence checks used `Path.exists()` without considering symlinks. A dangling
  symlink is "not existing" to `exists()` yet is still a journal path that must
  be rejected.
- Failure logging was delegated to the CLI boundary, so library-level journal
  failures were silent. Incomplete-usage visibility was limited to failure
  attempts.
- The test helper was written quickly and imported lazily without documenting a
  circular or optional-dependency exception.

## Solution

- Always build an owned `httpx2.Client(follow_redirects=False, timeout=...)` in
  `_ensure_client`, with or without an injected transport, and pass it to the
  SDK. Track it for best-effort release and keep `max_retries=0`.
- Added `_journal_absent()`, which treats a symlink as present so replay raises
  `JournalError` before any spend value is returned.
- Wrapped replay and append operations with safe `ERROR` records
  (`[Metrics.replay]`, `[Metrics.append]`) that log only the event type and the
  sanitized journal error text, never row contents.
- Added a `WARNING` (`incomplete_usage`) whenever provider usage is present but
  the three core counters are inconsistent; measured counters and estimated
  charges remain separate.
- Moved the test helper import to module scope and added regression tests for
  the default client policy, dangling symlinks, journal failure logging,
  incomplete usage, and tool calls with thinking disabled.

## Prevention

- Assert SDK-level policy on the default construction path, not only on test
  transports.
- Treat filesystem absence checks as unsafe for security-sensitive paths; check
  `is_symlink()` in addition to `exists()`.
- Log at the layer that owns the failure, with safe codes and no payloads.
- Cover each reconciliation combination (tools with thinking on and off) as a
  separate material path.
- Keep helper imports at module scope; use a documented exception only for real
  circular or optional dependencies.

## Regression Evidence

Five new tests failed before the fix; two were added as missing coverage, and a
seventh covers mixed legacy/gateway aggregation after reopening one journal. All
pass afterward. Offline suites pass: 223 core and 231 full tests.
