# Repo-growth context test, runner metadata, and import-rule regressions

**Date:** 2026-11-21 19:31
**Files:** `tests/context/test_end_to_end.py`, `benchmarks/run.py`, `benchmarks/offline.py`, `benchmarks/baselines/**`, `tests/benchmarks/test_run.py`, `tests/cli/test_feature_offline_e2e.py`, `tests/cli/test_feature_recovery_e2e.py`
**Severity:** high

## Problem

Three blockers surfaced when verifying v1-08:

1. `uv run --locked pytest` failed at
   `tests/context/test_end_to_end.py::test_real_project_through_cli_with_generated_config`
   with `StopIteration`: the CLI context pack omitted the requested excerpt
   `lean_weave.app.create_llm_provider`.
2. The persisted benchmark runner artifact lacked the fields Task 6 requires:
   config/settings fingerprints, model/thinking/caps, check descriptors, exit
   code, retry counts, and verification status. `_fingerprint_config` was dead
   code.
3. Function-local imports in new `benchmarks/` code and tests violated
   `RULES.md` rule 1 (module-level imports only).

## Root Cause

- The real-project context test used the default 6000-token stage budget. Adding
  the `benchmarks/` fixture corpus enlarged the deterministic repository
  inventory, consumed the budget, and displaced the requested symbol excerpt.
  The test depended on global repository size rather than on its own inputs, so
  it broke when unrelated files were added.
- `run_offline_case`/`run_live_case` returned only status, reason, oracle, and
  duration. The settings descriptor was never wired in, so the "safe comparable
  fields" clause had no implementation despite a helper existing.
- Imports were added at call sites for convenience during implementation instead
  of at module top; `benchmarks.offline` was already imported by `run.py`, so no
  circularity justified the pattern.

## Solution

- The real-project context test now writes a generated config with
  `context.stage_prompt_tokens_max = 12000`, keeping the CLI integration path
  while making the excerpt admission independent of unrelated repository growth.
- Added `describe_settings()`: loads the effective (defaults-merged) operator
  config and projects a bounded `CaseSettings` descriptor with the config
  fingerprint, model/thinking/endpoint/output cap, effective workflow limits,
  approved write paths, and check descriptors (id/executable/argv/timeout/output
  cap/data-only flag). No config body or secrets are persisted.
- `CaseOutcome` now carries `exit_code`, `settings`, `retry_count`,
  `verification_status`, and check execution/pass/failure fields (unavailable
  stays `None`, never invented). Both offline and live paths populate them; the
  human summary prints exit and retry values.
- Moved all new inline imports to module top in `benchmarks/run.py`,
  `benchmarks/offline.py`, and the new test modules.
- Regenerated `benchmarks/baselines/v1-offline-baseline.json`, its summary, and
  the seven linked metrics reports with relative `metrics_path` values and the
  new fields. Added assertions for the descriptor fields.
- Added DEBUG `[FIX] runner_settings` logging (fingerprint/check count/model
  only).

## Prevention

- Integration tests that index the real repository must pin the retrieval budget
  or selectors they depend on; never rely on default budgets staying large
  enough as the repo grows.
- When a task requires persisted comparable metadata, assert the fields in a
  test — otherwise helpers like `_fingerprint_config` silently stay unwired.
- Keep all imports at module top; treat inline imports as a review-blocking
  violation unless a circular/optional-dependency exception is documented.
- Re-run the full offline suite after adding top-level directories that feed
  repository inventory; focused suites can miss cross-cutting source-size
  effects.
- Persist baseline artifacts with repo-relative paths so evidence is portable
  and does not leak the developer checkout location.
